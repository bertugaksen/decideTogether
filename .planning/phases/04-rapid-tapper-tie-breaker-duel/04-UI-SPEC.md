## Visual Anchor & Screen Hierarchy

### Primary Screen 1: Mode A (Online WebSocket Duel)
- **Primary Visual Anchor (Focal Point):** Center dynamic Tug-of-War indicator bar with the 5.0-second millisecond timer bar directly above it.
- **Visual Hierarchy:**
  1. *Focal Point:* Center Tug-of-War progress bar shifting in real-time between Paprika Red (`#D9381E`) and Basil Green (`#2D6A4F`) with active countdown timer bar.
  2. *Secondary:* Live tap score counter badges (host vs. peer) rendered in 48px display figures with tabular layout.
  3. *Tertiary:* Full-screen touch tapping pad with pulsing radial feedback ring on touch.
  4. *Quaternary:* Bottom status badge displaying opponent network connectivity and nickname.
- **Accessibility Fallback:** All icon-only buttons include `aria-label` fallback text (e.g. `aria-label="Parmak güreşi kurallarını göster"`).

### Primary Screen 2: Mode B (Single-Phone Split-Screen Mode)
- **Primary Visual Anchor (Focal Point):** Center horizontal dividing seam (56px) containing the dual Tug-of-War bar, 5.0s countdown timer, and neutral score tally.
- **Visual Hierarchy:**
  1. *Focal Point:* Central Dividing Seam (56px height, `#1C1917` background with `#E7E2D9` border) displaying the real-time rope-pull tension meter.
  2. *Secondary:* Top half (Player 1 / Host, rotated 180° for opposite seated player) in Paprika Red (`#D9381E`) with bold "DOKUN! 🔥" prompt and tap counter.
  3. *Tertiary:* Bottom half (Player 2 / Peer, normal orientation) in Basil Green (`#2D6A4F`) with bold "DOKUN! ⚡" prompt and tap counter.
  4. *Quaternary:* Countdown overlay ("3-2-1 BAŞLA!") pulsing across the center before the battle begins.
- **Accessibility Fallback:** Split-screen touch arenas include distinct visual labels ("Oyuncu 1" and "Oyuncu 2") with 180° rotation for seated ergonomic clarity.

| Destructive | `#D9381E` (Paprika Red) | "Odadan Ayrıl" destructive exit action |

### Accent Color Reservation List
Accent colors (`#D9381E` Paprika Red and `#2D6A4F` Basil Green) are strictly reserved for the following 5 elements (never applied generically to all interactive elements):
1. **Primary Duel Action Button:** "Parmak Güreşini Başlat" CTA button in `DeckExhausted` modal (`#D9381E`).
2. **Player 1 Arena & Indicator:** Player 1 split-screen pad background, Player 1 live score badge, and left progress segment of Tug-of-War bar (`#D9381E`).
3. **Player 2 Arena & Indicator:** Player 2 split-screen pad background, Player 2 live score badge, and right progress segment of Tug-of-War bar (`#2D6A4F`).
4. **Millisecond Timer Progress Bar:** Active 5.0s battle countdown timer bar depleting across the screen (`#D9381E`).
5. **Celebration Winner Accent:** Post-duel victory badge and confetti particle blast in `MatchCelebration` (`#D9381E` and `#2D6A4F`).

## UI Considerations

Applicable state considerations resolved: 8 covered, 0 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Tap Counters & Tug-of-War Bar | ✅ covered | At 0-0 before battle begins, Tug-of-War bar remains perfectly centered at 50% using Laplace smoothing ($k=4$). Numerical score displays render "0" alongside empty-state instructional copy. |
| loading | Countdown & Web Audio Unlock | ✅ covered | When initiating duel, a 3.0-second synchronized modal overlay renders animated numbers ("3-2-1 BAŞLA!") with synthesized Web Audio 523Hz/1046Hz tones. Tap surfaces remain locked and non-responsive until "BAŞLA!" triggers. |
| error | WebSocket Disconnect during Duel | ✅ covered | If peer or host disconnects mid-battle, client continues optimistic local tap counting while showing a non-blocking toast. If disconnected beyond 350ms post-battle grace, server and client fall back to error state with reconnection timer. |
| populated | Active 5.0-Second Battle | ✅ covered | Happy-path battle renders 60fps local tap increments with 15ms haptic vibration pulses, dynamic Tug-of-War bar shifting via cubic-bezier transition, and millisecond timer bar shrinking from 100% to 0%. |
| partial | Network Jitter / Unbalanced Tap Packets | ✅ covered | In Mode A, cumulative tap tallies sent every 75-100ms prevent packet loss desynchronization. Laplace smoothing ($k=4$) prevents the Tug-of-War meter from erratically bouncing on single packet arrivals. |
| overflow | Rapid Score Accumulation (>100 taps) | ✅ covered | Numerical tap counters utilize `tabular-nums` CSS and fixed container bounding boxes (`min-w-[4rem] text-center`) to prevent layout shifts or horizontal clipping during rapid multi-finger tapping. |
| zero-one-many | Winner Liked Restaurant Selection | ✅ covered | Authoritative server queries `room.votes[winnerId]`: if winner has 1+ likes, top-rated is chosen; if winner has 0 likes, peer's top liked venue is chosen; if both have 0 likes, deck venue 0 is chosen. |
| long-text | Nicknames & Venue Names | ✅ covered | Participant nicknames in score badges truncate at 15 characters with ellipsis (`truncate max-w-[120px]`). Restaurant name in final match celebration is capped at 2 lines with standard font-display clamp. |
